1. **C-key axis clipping.** In the C key the note axis started at `C#` and had

   lands on both screen edges. Fix: widen the CQT frame a half-semitone each

   `filtergraph.py` and to the axis PNG's `note_x` so they stay aligned), and

   check was a false all-clear — the video rendered, the axis just vanished.
   Fix: hand `showcqt` a safe-named tempfile copy of the axis PNG, the same
   trick `title_file` already uses. See `render/__init__.py` `render_track()`.

## Open problem: guitar bleed

### Symptom
On some tracks the "bass only" output has audible guitar. User spot-checks:
- Track 06 (Dyna Flow): guitar clear, loud, **high-pitched**.
- Track 07 (Uptown Up): faint guitar.
- Tracks 08, 11: fine.
- Track 40 (Thrill Is Gone): guitar present in mix and in bass.wav.
- Only spot-checked through ~11 and 40; **full extent unknown**.

### Root cause (confirmed + refined by research)
The format is L = full mix, R = full mix **minus bass**, so bass = L − R.
But L and R are **separately-mastered stems**, so the non-bass content is NOT
identical between channels. Model it as `R = H·m` where `m` is the non-bass mix
and `H(f)` is an unknown transfer (level + phase + small delay + mastering EQ).
Then naive `L − R = bass + m·(1 − H)` — the residual `m·(1−H)` is nonzero
whenever H ≠ 1. That residual is the leaked guitar/vocals.

The current pipeline (`extract.py` `build_filter()`) is
`pan=mono|c0=c0-c1,lowpass=f=800`. The `lowpass` is a gentle 2nd-order biquad
(−12 dB/oct). It cannot remove guitar that sits in the bass harmonic band, and
on the worst tracks guitar even survives *above* 800 Hz (the "high-pitched"
symptom). **Raising the lowpass corner does not help** — it re-admits the
guitar it's meant to remove. The fix belongs in the *cancellation* layer, not
the filter.

### Measurement so far (rough, imperfect)
Scanned all 43 source tracks for L−R residual mean-volume in three bands:
`bass` (<250 Hz), `250-800`, `>800`. The `250-800` column roughly tracks
audible guitar (worst: 30, 14, 13, 25, 17, 18, 06, 10, 41, 09; cleanest: 22,
27, 24, 42, 20). The `>800` column is the "high-pitched" tell (worst: 25, 17,
30, 13, 21, 18, 09, 43, 10, 06).

**The user correctly flagged this metric is weak.** 04/05 sound okay but score
close to 07 which is mixed — they're within ~1.5 dB, the metric's noise floor.
A whole-track mean also washes out *where* the leak sits in time: a track that
leaks loudly in bass-quiet gaps sounds much worse than the number implies. A
better metric = residual energy **relative to bass, measured during bass-silent
windows** (reuse `detect.py`'s silence windows). Build this alongside the fix so
we can score before/after objectively across all 43.

## Researched fix (recommended plan)

Full research report was generated this session (agent findings). Headline: the
setup is textbook **adaptive noise cancellation** — the reference channel (R)
contains the interference (guitar) but not the target (bass), so we can subtract
the guitar without touching the bass. All feasible with **numpy/scipy** (already
transitive via librosa) — **no torch / no heavy ML deps**.

Recommended order, value-per-cost:

1. **Time-align R to L** before subtraction. Estimate integer + sub-sample
   offset via `scipy.signal.correlate` cross-correlation; apply fractional
   delay. Near-zero cost, can't hurt bass (bass isn't in R), often a big win if
   stems are offset. Do unconditionally.

2. **Replace naive L−R with per-bin complex-gain projection** — the headline
   fix. Per STFT bin, estimate the complex gain `Ĥ[k] = ⟨L·conj(R)⟩ /
   ⟨|R|²+ε⟩`, estimated **only on bass-free frames** (reuse `detect.py` silence
   windows; high bins are naturally bass-free), then output
   `b̂ = ISTFT(L[k,t] − Ĥ[k]·R[k,t])`. This directly cancels the
   mastering/level/phase mismatch at every frequency, leaves bass untouched
   (bass uncorrelated with R), and reduces to plain L−R when Ĥ=1. One STFT/ISTFT
   pair, seconds per track. **Guardrail:** fit Ĥ only on bass-free content or it
   will partially cancel bass; keep the low band lightly processed.

3. **Swap the ffmpeg backstop filter** `lowpass=f=800` →
   `asupercut=cutoff=800:order=8` (~−48 dB/oct, flat passband preserves bass
   harmonics). One-line change in `build_filter()`. Cleanup only, after step 2.
   Portable fallback: chain `lowpass=f=800,lowpass=f=800` for −24 dB/oct.

4. **Optional `--denoise`** spectral gate keyed on a bass-silent residual window
   (`noisereduce` PyPI, light; or hand-rolled spectral subtraction). Opt-in for
   the worst tracks. Gentle to avoid warble / bass dulling.

5. **Stubborn tracks only: NLMS adaptive FIR** (R→leak), ~20 lines of numpy;
   handles delay+phase+EQ+drift jointly, can subsume steps 1–2.

6. **Last resort, opt-in heavy path: Demucs** behind an optional dependency
   group. Best use is NOT as primary extractor (that throws away the near-perfect
   subtraction) but as per-track rescue/blend, or as the generator of a clean
   guitar reference to feed the step-4 gate.

**Do NOT** just raise the lowpass corner — that's the wrong layer.

### ⚠️ Hard constraint: don't break click/window detection
The current `_bass.wav` (plain L−R + lowpass) is **depended on downstream** by
`detect.py` for silence-gap and count-in "ghost click" detection — those clicks
survive *because* naive L−R leaves the non-bass residual in. A better
cancellation (steps 1–2) that removes that residual would also remove the clicks
`detect.py` needs. So the cleaner bass is **not a drop-in replacement** for the
detection input.

Design implication: the cancellation must be an **additional/parallel output**,
not a replacement. Likely shape — keep the existing L−R+lowpass pass as the
detection/window input (the "dirty" bass), and produce the cleaned bass as a
separate artifact for the *audible* `bass_only.m4a` + render visuals. Confirm in
brainstorming which downstream consumers read which file (detect → dirty;
combine/remix/encode/render → clean?) and thread the two paths through
`pipeline.py` accordingly. This is a key thing to nail in the spec before
building.
